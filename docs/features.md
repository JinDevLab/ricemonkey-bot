# 기능 명세
분배 규칙과 용어는 [도메인 문서](domain.md)를 따른다.

## 1. 봇의 역할
봇은 기존 분배 방식의 계산과 멘션, 진행 확인을 대신한다. 게임 안의 거래는 볼 수 없으므로 상태는 사람이 누른 표시만을 기준으로 한다.

## 2. 1차 범위

| 단계 | 하는 사람 | 봇의 동작 |
|---|---|---|
| 분배 만들기 | 분배자 | `/분배` 실행 시 입력창을 열어 총판매금액, 판매 수수료, 파티원 1~5명을 받고 정분배로 경매장 등록가를 계산한다. |
| 비율 조정 | 분배자만 | 진행 중이며 아무도 경매장 등록을 제출하지 않았을 때 카드의 버튼으로 비율 입력창을 열어 다시 계산한다. 금액이 바뀌었거나, 제출한 카드의 금액이 현재와 다른 파티원에게 재확인 알림을 보낸다. |
| 금액 안내 | 봇 | 파티원을 멘션하고 각자 경매장 등록가와 예상 실수령액을 보여준다. |
| 경매장 등록 | 해당 파티원 본인만 | 버튼으로 입력창을 열어 경매장에 등록한 아이템 이름(필수 한 줄, 최대 100자)을 받고 분배자에게 이름과 금액을 알린다. 구매 전에는 다시 눌러 수정할 수 있다. |
| 구매 완료 표시 | 분배자만 | 경매장 등록을 제출한 파티원만 구매 완료로 바꾸고 해당 파티원에게 아이템 이름과 실수령액을 카드가 있는 채널(비공개 분배는 스레드)에 알림으로 보낸다. 분배자는 알림 대상이 아니다. |
| 분배 완료 | 봇 | 전원이 구매 완료면 메시지를 완료 상태로 바꾸고 이모지를 남긴다. |
| 분배 취소 | 분배자만 | 잘못 입력하면 취소하고 다시 만든다. 이미 구매한 건은 봇이 되돌리지 못한다. |
| 미완료 조회 | 누구나 | 내가 등록해야 하는 건과 내가 구매해야 하는 건을 보여준다. |
| 내역 조회 | 누구나 | 내가 분배자나 파티원으로 참여한 분배를 최근 순으로 보여준다. 날짜, 분배자, 총판매액, 내 몫, 상태를 표시하고 조회한 본인에게만 보인다. |

### 서버 전용 명령
- `/분배`: 슬래시 옵션 없이 입력창을 연다. 모든 칸은 Label로 감싼다. `총판매금액`은 필수 한 줄(최대 21자), `수수료`는 필수 Radio Group(3%/5%), `파티원`은 User Select(본인 제외 1~5명)다. 제출하면 공개 카드를 새로 게시한다. 파티원 표시 순서는 제출된 values 순서이고 금액은 순서에 영향을 받지 않는다.
- `/미완료`: 내가 등록해야 하는 건과 내가 구매해야 하는 건을 각각 오래된 순 10행까지 본인에게만 보여준다. 11행을 조회해 더 있으면 “더 있어요”를 표시한다. UUID는 표시하지 않는다. 올릴 건에는 분배자, 경매장 등록가, 채널, 생성일을, 구매할 건에는 파티원, 아이템 이름(등록 전은 대기), 금액, 상태, 채널, 생성일을 표시한다. 안내와 조회는 임베드 카드로 보여 준다.
- `/미완료`의 표시 항목은 같은 분배에 같은 번호를 붙인다(최대 20개). String Select로 고르면 분배자 또는 제외되지 않은 파티원만 원래 채널에서만 새 공개 카드를 게시할 수 있다. 다른 채널이면 원래 채널에서 `/미완료`를 실행하도록 안내한다. `/미완료`에 나오는 건만 고를 수 있고, 이미 등록을 마친 파티원은 본인 목록에 안 나오므로 분배자가 다시 올린다. 원래 채널이 지워지면 다시 올릴 수 없고 생성 후 3개월 뒤 자동 삭제된다. 재게시에는 멘션 알림이 없고 종료 건은 거절하며 옛 카드도 동작한다.
- `/미완료`와 `/내역` 날짜는 Discord 타임스탬프(`<t:유닉스초:d>`)로 표시해 보는 사람의 현지 날짜로 보여준다.
- `/내역`: 이 서버에서 내가 참여한 분배 중 취소 건을 제외한 최근 10건을 본인에게만 보여준다. 취소 건은 10건 제한을 차지하지 않으며 생성 후 3개월 보관 뒤 자동 삭제한다. 페이지 넘김은 없다.
- 등록 전 구매 완료 버튼은 잠기며 서버와 DB에서도 거절한다. 파티원이 경매장 등록 버튼을 눌러 제출해야 구매 완료가 가능하다. 누르기 전에는 분배자가 비율을 조정하거나 취소할 수 있다. 기존 uploaded 기록은 이름이 NULL이어도 구매 가능하다.
- 구매 알림은 실제 상태 전환 때만 원본 갱신 callback 성공 후 보낸다. 파티원만 멘션 알림 대상이며 분배자·전체 멘션은 비활성화한다. 마지막 구매에도 알리고 완료 리액션을 시도한다. 토큰이 없으면 type 7 갱신만 하며, callback·알림 실패는 상태를 되돌리거나 재시도하지 않고 action(알 수 있을 때)과 status만 기록한다.
- 모든 조회는 현재 서버로 한정하며 멘션 알림을 보내지 않는다.

### 비공개 분배 패널
- `/분배패널`은 서버 설치·서버 전용이며 기본 실행 권한은 서버 관리(`32`)다. 일반 텍스트 채널에 공개 안내와 `비공개 분배 만들기` 버튼 하나를 멘션 없이 올린다. `/분배`의 공개 동작은 바꾸지 않는다.
- 패널·버튼·입력 제출에서 일반 텍스트 채널 여부와 봇의 채널 보기, 비공개 스레드 만들기, 스레드에서 메시지 보내기, 링크 첨부, 메시지 기록 보기, 반응 추가를 검사한다. 실패는 본인에게만 알린다. 스레드 안에서는 시작할 수 없다.
- 버튼은 `/분배`와 동일한 필드로 `비공개 분배` 입력 창을 연다. 누른 사람이 분배자다. 입력 검증, 토큰·봇 권한·확인 가능한 파티원의 채널 보기 권한 검사 후 본인 전용 지연 응답을 보낸다. 파티원 권한 값이 없으면 초대를 시도한다.
- `분배 · <분배자 표시 이름>`(100자 이내)으로 type 12, invitable false, 7일 무활동 자동 보관 스레드를 만든다. 이름에는 금액·아이템을 넣지 않는다. 분배자 다음 파티원 순서로 추가하고 하나라도 실패하면 DB 저장·카드 게시 없이 중단한다. 빈 스레드가 남을 수 있고 자동 재시도는 없다.
- 모두 초대된 뒤 스레드 ID와 `private_thread = 1`을 저장하고 스레드에 기존 카드를 멘션과 함께 게시한다. 카드 실패 시 같은 batch로 멤버·분배를 삭제한다. 삭제도 실패하면 `/미완료` 복구를 안내한다. 실패 시 공개로 대체하지 않고 `/분배`가 공개라는 점을 알린다.
- 비공개 분배의 재게시는 같은 스레드면 기존 응답 방식, 다른 채널이면 스레드에 REST로 멘션 없이 게시하고 본인에게 링크만 안내한다. 토큰 없음·실패 시 카드 없이 본인 전용 실패 안내만 한다. 앞의 공개 재게시 채널 제한은 `private_thread = 0`에만 해당한다. 참여자·종료 검사와 조회 목록 표시는 그대로다.
- 카드 갱신과 등록·구매·비율 알림은 해당 스레드의 상호작용을 따른다. 스레드 관리 권한자는 초대 없이 열람할 수 있다. 0% 제외자는 내보내지 않고, 완료·취소 시 잠금·보관하지 않는다. Manage Threads 권한은 요구하지 않는다. 보관된 스레드 재게시 시 보관 해제 등 실제 Discord 동작은 미확인이다.

### 비율 조정
- 분배자만 사용할 수 있고 진행 중이며 uploaded/purchased 파티원이 한 명도 없어야 한다. 버튼 클릭과 모달 제출 때 권한·상태를 다시 검사한다. 종료된 분배는 최신 카드만 보여 주고 입력 오류는 기존 카드를 그대로 둔다.
- 칸은 모두 Label + 선택 한 줄 입력(최대 7자)이다. 파티원 4명 이하면 분배자 칸과 파티원 칸, 5명이면 파티원 칸만 제공하고 제목은 `비율 조정 (분배자는 빈 칸처럼 계산)`이다. 0%로 제외된 파티원도 포함하고 현재 지정 비율은 미리 채운다. 표시 이름은 45자까지 쓴다.
- 앞뒤 공백을 지우고 빈 칸·공백만 있는 칸은 미지정으로 처리한다. 5명일 때 다섯 칸을 모두 채우면 분배자가 나머지를 받으며, 합이 100%면 분배자 비율을 0으로 계산·저장한다. 합이 100% 미만이거나 빈 칸이 있으면 분배자를 미지정으로 저장하고, 빈 칸의 파티원과 남은 몫을 똑같이 나눈다. 합이 100%를 넘으면 거부한다. 총판매액·수수료·판매 실수령액은 그대로 두고 등록가·예상 실수령액·분배자 최종 금액만 다시 계산한다. 등록가 0이면 제외, 나머지는 대기로 저장한다.
- 하나의 D1 batch로 저장하며 그 사이 등록자가 생겼으면 부모·파티원 모두 바꾸지 않는다. 저장 실패 시 최신 상태가 종료됐으면 그 카드를 다시 그리고, 진행 중이면 등록으로 잠겼다는 안내를 보낸다. 갱신 성공 후 금액이 바뀌었거나, 제출한 카드의 금액이 현재와 다른 파티원을 멘션한다. 새 금액이 양수인 사람에게는 `분배자님이 비율을 바꿨어요. 경매장 등록가를 다시 확인해 주세요.`, 0인 사람에게는 `분배자님이 비율을 바꿔서 이번 분배에서 제외됐어요. 이미 올렸다면 내려 주세요.`를 한 메시지의 별도 줄로 보내며 해당자가 없는 줄은 뺀다. 분배자는 알림 대상이 아니다. DB 금액이 바뀐 파티원과 제출한 카드 본문에 새 금액이 반영되지 않은 파티원의 합집합을 알린다. callback 실패 후 같은 값으로 재제출해도 빠진 알림을 복구할 수 있다. 옛 카드에서 제출하면 이미 알림을 받은 파티원에게 중복 알림이 갈 수 있다. 본문을 읽지 못하면 DB 비교만 쓰고, 카드와 DB가 모두 같으면 알림은 없다. 자동 재시도는 없다. 게임 안에서 먼저 올렸을 가능성 때문에 재확인이 필요하다.

### 비율 표시
- 안내 카드에서 분배자와 0% 제외 파티원의 정확한 비율이 모두 같으면 퍼센트를 숨긴다. 하나라도 다르면 전원에게 표시하며 0% 분배자도 포함한다.
- 미지정 비율은 분배자와 제외 파티원을 포함한 모든 지정 비율의 합을 100%에서 빼고 미지정 인원이 균등 분배한다. 같은지 비교는 반올림 전에 수행한다.
- 소수점 둘째 자리까지 반올림하고 뒤의 0을 뺀다. 반올림 때문에 표시 합계는 100%가 아닐 수 있다. 금액 계산은 바꾸지 않는다.

### 금액 표시
- 금액은 끝에서 네 자리씩 끊어 억·만 단위를 붙이고, 0인 자리도 생략하지 않으며 공백 없이 모든 자릿수를 표시한 뒤 ` 메소`를 붙인다. 예: `2억0005만0000 메소`.
- 경매장 등록가는 단위 표기만 굵게 하고, 뒤에 쉼표·공백·서식 없는 원래 숫자를 괄호로 덧붙인다. 예: `**2억4619만2893 메소** (246192893)`.

## 3. 입력 검증과 기록 보관
- 분배 퍼센트는 `50`과 `50%` 모두 허용한다. 끝의 `%`는 하나만 가능하며 0~100, 소수점 둘째 자리까지 입력한다. 앞뒤 공백은 지워 ` 30 `도 허용하며 빈 칸이나 공백만 있는 칸은 미지정으로 처리하고, 숫자에 섞인 공백(`50 %` 포함)·지수 표기·셋째 소수자리는 거부한다.
- 총판매금액은 앞뒤 공백을 지우고 숫자만 또는 `240,000,000`처럼 세 자리마다 쉼표를 넣은 형식만 허용한다. `2,4,0`·문자·0·안전 정수 초과는 거부한다. 수수료는 정확히 `3` 또는 `5`만 받는다.
- 입력 검증 — 파티원 중복, 봇 계정, 분배자 본인을 파티원으로 넣는 경우, 파티원 정보 누락, 1~5명의 문자열 배열이 아닌 파티원 선택은 거부한다. 모든 파티원의 몫이 0%인 분배도 거부한다.
- 아이템 이름은 앞뒤 공백과 줄바꿈을 정리해 원문으로 저장하고, 출력 시 마크다운·멘션·링크 문법을 이스케이프한다. 입력창 ID `item;<splitId>;<listing_amount>`와 Label 설명에 현재 금액을 넣어 게임 등록가를 확인하게 한다. 옛 형식과 잘못된 형식은 쓰기 없이 버튼을 다시 누르게 한다. 입력창을 연 뒤에도 제출 시 권한과 현재 상태를 다시 확인하고, 제출 금액이 현재 등록가와 다르면 새 금액으로 재확인을 안내한다. DB 저장에도 동일 금액 조건을 걸며 그 사이 변경으로 저장이 실패했으면 카드를 갱신하지 않는다. 0%로 제외됐으면 기존 본인 등록 권한 문구로 거부한다. 구매 완료·분배 종료 후에는 저장하지 않고 원본 메시지의 최신 상태를 보여 준다. 기존 등록 기록의 이름이 비어 있으면 `아이템 미입력`으로 표시한다.
- 완료·취소·진행 중을 포함한 모든 분배와 파티원 기록은 생성 후 달력 기준 3개월이 지나면 매일 KST 03:00에 자동 삭제한다. UTC 기준 시각과 정확히 같으면 남기고 월말은 대상 월의 마지막 날로 맞춘다. Discord 카드 메시지는 삭제하지 않는다.
- 분배 퍼센트가 0%인 파티원은 금액 안내와 버튼 대상에서 빼고 전원 구매 완료 판단에서도 제외한다. 분배 기록에는 몫 0으로 남긴다.

## 4. 1차에서 제외
- 아이템별 드랍 기록: 분배자가 합계만 입력하므로 필요 없다. 파티원이 분배금을 받으려고 경매장에 올린 아이템 이름 기록과는 다르다.
- 고정 파티 저장: 편의 기능이라 실제 사용해 보고 필요하면 추가한다.
- 넥슨 Open API 연동: 분배 계산에 필요 없다.
