## 4. 구현 중 내린 결정
- [x] 모든 파티원의 몫이 0%인 분배는 받을 사람이 없으므로 거부한다.
- [x] 안내 메시지 바로가기 링크는 저장하거나 제공하지 않는다. 미완료에는 UUID 대신 상대방, 금액, 채널, 생성일을 표시하고 구매할 건에는 상태도 표시한다.
- [x] 내역은 취소 건을 제외한 최근 10건이고 페이지 넘김은 없다. 취소 기록은 보관하지만 조회 제한을 차지하지 않는다. 조회는 현재 서버로 한정한다. 날짜는 Discord 타임스탬프로 표시해 보는 사람의 현지 날짜를 쓴다.
- [x] 미완료는 오래된 건이 숨지 않도록 오래된 순으로 각각 11행을 조회해 10행만 보여 주고, 11번째가 있으면 “더 있어요”를 표시한다. 구매할 건은 파티원별 한 행이다. 페이지 넘김은 없다.
- [x] `/분배`는 옵션 없이 Label 모달을 열고 총판매금액·수수료 Radio Group·파티원 User Select를 받는다. 총판매액은 앞뒤 공백을 지우고 숫자와 세 자리마다의 쉼표만 허용하며 양의 안전한 정수여야 한다. 새 분배는 모두 미지정 비율(정분배)이다.
- [x] 비율은 진행 중이며 등록·구매자가 없을 때 분배자만 카드의 `비율 조정`으로 바꾼다. 파티원 5명이면 분배자 칸을 생략한다. 다섯 칸을 모두 채우면 분배자가 나머지를 받고(합이 100%면 0%), 빈 칸이 있으면 분배자도 그 사람들과 남은 몫을 똑같이 나눈다. 빈 칸·공백만 있는 칸은 미지정이고 0% 제외 파티원도 다시 입력할 수 있다. 퍼센트는 정수 hundredths로 바꾸며 셋째 소수자리는 거부하고 끝의 `%` 하나는 허용한다.
- [x] 비율 저장은 부모·멤버 UPDATE 모두 guild·distributor·active·등록/구매자 없음 조건을 걸고 하나의 D1 batch로 처리한다. 금액이 실제 바뀐 파티원에게만 카드 갱신 callback 성공 후 재확인 알림을 보낸다.
- [x] 동시 클릭에서 DB 상태는 조건부 UPDATE로 보존한다. 늦게 도착한 응답 때문에 메시지가 이전 상태로 보일 수 있고, 권한 있는 사람이 다시 누르면 DB 최신 상태로 다시 그려진다. 권한 없는 사람은 상태와 무관하게 비공개 거절만 받는다. 별도 자동 동기화 작업은 없다.
- [x] 등록 전 구매 완료는 버튼·서버·DB에서 거절한다. 파티원이 경매장 등록을 제출하기 전에는 분배자가 비율을 조정하거나 취소할 수 있다. uploaded의 NULL 이름은 구매 가능하다.
- [x] 안내 카드 비율은 분배자와 제외되지 않은 파티원의 정확한 비율이 같으면 숨기고 다르면 모두 표시한다. 미지정 몫은 모든 지정 비율을 뺀 나머지를 균등 분배한다. 소수점 둘째 자리 반올림과 끝의 0 제거로 표시하며 표시 합계가 100%가 아닐 수 있다.
- [x] 실제 구매 완료 전환 후 callback 성공 뒤 해당 파티원에게 아이템 이름과 실수령액을 공개 알림으로 보낸다. 분배자는 멘션 알림 대상이 아니며 재클릭은 재전송하지 않는다. callback·알림 실패는 action(알 수 있을 때)과 status만 기록하고 DB를 되돌리거나 재시도하지 않는다.
- [x] 토큰이 없으면 일반 type 7 응답으로 상태만 갱신하고 알림·리액션을 건너뛴다. 후속 알림·리액션 실패는 로그만 남기며 DB를 되돌리거나 자동 재시도하지 않는다.
- [x] 경매장 등록 callback 전송 자체가 실패해도 DB는 `uploaded`와 입력 이름을 유지한다. 자동 재시도는 없고, 구매 전에는 버튼을 다시 눌러 모달을 제출하면 수정 알림을 보낼 수 있다. 화면은 갱신되지 않을 수 있으며 분배자는 `/미완료`로 이름을 확인할 수 있다. `DISCORD_TOKEN`이 틀리면 callback까지 실패할 수 있다(라이브러리가 Bot Authorization을 사용하므로 생기는 추정이며 실제 Discord에서는 미확인).
- [x] 버튼의 `uploaded;<splitId>`와 DB의 `uploaded` 상태는 호환성을 위해 유지하고 화면에는 `경매장 등록`·`등록 완료`로 표시한다. 모달 ID는 `item;<splitId>;<listing_amount>`이고 Label 설명에 현재 금액을 표시해 게임 등록가를 재확인한다. 옛 형식·잘못된 형식은 쓰기 없이 버튼 재클릭을 안내한다. 제출 시 금액이 달라졌으면 새 금액으로 재확인을 안내하며 저장하지 않는다. 저장은 active 분배의 pending/uploaded 행이면서 제출 금액과 listing_amount가 같을 때만 적용한다. 읽기와 저장 사이 변경으로 저장이 실패해도 카드를 갱신하지 않고 재확인을 안내하며, 제외됐다면 본인만 등록할 수 있다는 기존 문구로 거부한다. 첫 등록 시각은 수정해도 유지한다.
- [x] `/분배`에서 연 모달은 제출 시 새 공개 카드(type 4)를 게시한다. 비율 조정·경매장 등록 모달은 버튼에서 열고 원본 메시지가 있는 제출에만 type 7을 사용한다. 버튼 모달의 메시지가 없는 제출은 비공개 안내로 거절한다. 제출 시 권한·상태를 다시 검사하고, 구매·종료 후 제출과 권한 있는 버튼 클릭은 최신 상태를 다시 그린다.
- [x] 테스트 D1 초기화에는 명시적인 비밀값 없는 환경 파일 경로를 지정한다. Wrangler는 `envFiles: []`만으로는 `.dev.vars` 로드를 막지 않으므로 빈 배열은 쓰지 않는다.
- [x] 등록 스크립트는 Node 24의 타입 제거와 `--env-file-if-exists=.dev.vars`를 쓴다. 파일이 없어도 누락된 필수 변수 안내를 출력하고 API 호출 없이 종료하기 위해 `--env-file` 대신 선택했다. 길드 등록에서는 전역 전용 필드 `contexts`, `integration_types`를 제거한다.
- [x] 새 의존성 없이 Wrangler `getPlatformProxy({ persist: false })`의 실제 로컬 D1을 테스트한다. 기존 계산 모듈과 서명 테스트 파일은 변경하지 않았다.
- [x] Workers Logs는 Free에도 포함되어 `observability.enabled`를 켰다. 2026-10-31 확인 기준 무료는 하루 200,000 events, 보관 3일이며 무료 초과 과금 항목은 없다. Paid는 월 20,000,000 events 초과분에 $0.60/백만 events가 붙으므로 유료 전환 전 재검토한다. 2026-12-01부터 Observability 요금제로 전환되며 Free는 하루 0.5GB 수집·7일 보관, 초과 시 수집 중지 후 00:00 UTC에 재개한다. 무료 플랜에 자동 초과 과금은 없다.
- [x] Node 24 테스트에서는 `zz`, `abc`, `00` 서명도 라이브러리가 401을 반환하지만, 실제 Wrangler 로컬 런타임에서 형식 검사 래퍼를 우회하면 `zz`가 hex 변환 예외로 500을 반환하는 것을 재현했다. 래퍼 복원 후 401을 확인했다. 런타임별 `Uint8Array.fromHex` 차이가 원인이다.

## 6. 사용자가 결정할 것
- [ ] 안내 메시지가 지워지면 버튼이 사라져 그 분배를 취소·구매 처리할 수 없고 `/미완료`에 계속 남는다. 대안은 `/미완료`에 버튼을 붙이거나 취소 명령을 추가하는 것이다.
- [ ] 등록 전 구매 클릭은 버튼·서버·DB에서 막았다. 등록 후 구매 완료 오클릭은 여전히 되돌릴 수 없다. 마지막 오클릭은 즉시 분배 완료 처리된다. 되돌리기 기능이 필요한지 결정한다.
- [ ] 취소 버튼에는 확인 단계가 없다. 추가 확인이 필요한지 결정한다.
