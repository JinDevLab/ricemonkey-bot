# 1.0 전 작업과 확인 기록

## 1. 배포·실행 사실과 소유자 결정
- [x] Cloudflare 계정 인증, D1 생성, Worker 바인딩, Discord 앱·봇·Endpoint 설정과 테스트 서버 초대를 완료했다.
- [x] 현재 배포 버전은 0.4.0이다. 기존 마이그레이션은 0002(`item_name`)까지이며 이번 변경에는 새 DB 구조나 마이그레이션이 없다.
- [x] 소유자가 2026-10-31 테스트 서버에서 0.4.0의 `/분배` 창, 카드 게시, 비율 조정, 옛 금액 차단, 등록, 구매 흐름을 확인했다. 아래의 세부 미확인 항목까지 모두 검증했다는 뜻은 아니다.
- [x] 소유자가 Cloudflare Metrics 화면에서 호출 72회, 오류 0, CPU 2ms, Wall 201ms를 봤다. 통계 종류(평균·중앙값·백분위 등)는 화면에서 확인하지 못했다. 적은 트래픽 관측이며 무료 CPU 한도를 항상 만족한다는 증거는 아니다.
- [x] 실제 파티 사용과 전역 명령 표시는 소유자 결정으로 1.0 판단에서 확인된 것으로 간주한다. **이는 실제 실행 기록이 아니다.**
- [x] 전역 명령 3개 등록과 테스트 서버 지정 명령이 비어 있음은 2026-10-31 Discord 조회로 확인했다. 이번 구현 작업에서 Discord API를 다시 호출한 것은 아니다.

## 2. 이번 구현
- [x] 생성 후 달력 기준 3개월이 지난 모든 상태의 분배를 매일 KST 03:00에 삭제한다. UTC 월말을 보정하고 경계와 같은 기록은 남긴다. 하나의 D1 batch에서 멤버를 먼저 삭제한다. 성공 로그는 건수, 실패 로그는 오류 이름만 남긴다.
- [x] `/미완료`는 올릴 건·구매할 건 각각 오래된 순 11행을 조회해 10행씩 보여 준다. 같은 분배에 같은 번호를 붙이고 최대 20개 고유 분배를 선택해 현재 채널에 공개 카드를 다시 올린다. 분배자·제외되지 않은 파티원만 허용하고 종료 건은 거절한다. 알림을 다시 울리지 않으며 옛 카드도 동작한다.
- [x] 완료 리액션은 생성 채널이 아니라 버튼을 누른 메시지의 채널에 보낸다.
- [x] 비율 변경 알림 대상은 DB 금액 변경자와 제출 카드가 새 금액과 다른 파티원의 합집합이다. callback 실패 뒤 같은 값으로 제출해도 알림을 복구한다. 본문을 읽지 못하면 DB 비교만 쓰며 자동 재시도는 없다.
- [x] 명령 등록은 `npm run register:global`과 `npm run register:guild`로 명시한다. 전역은 서버 ID를 무시하고 서버 등록은 ID가 필수다. 서버 지정 명령은 전역과 겹쳐 보일 수 있다.
- [x] MIT 라이선스, [개인정보 안내](privacy.md), 문의와 운영자 삭제 요청 절차를 추가했다. 완료·취소 기록도 생성 후 3개월 보관 뒤 자동 삭제한다.
- [x] Node 24에서 설치·타입 검사·테스트·배포 dry-run을 실행하는 비밀값 없는 CI를 추가했다. CD는 보류하고 수동 릴리스를 따른다. CI 필수화 ruleset은 아직 설정하지 않았다.

## 3. 로컬 검증과 제약
- [x] 테스트는 Wrangler `getPlatformProxy({ persist: false, envFiles: ['test/.no-secrets.env'] })`의 실제 로컬 D1과 마이그레이션을 쓴다. 환경 파일은 존재할 필요가 없다. `envFiles: []`는 `.dev.vars` 자동 로드를 막지 못하므로 쓰지 않는다.
- [x] Ed25519 키는 테스트마다 생성하고 Discord 요청은 가짜 토큰과 fetch mock으로만 검증한다. 등록 스크립트도 Node 자식 프로세스에서 fetch를 교체하므로 실제 API를 호출하지 않는다. 계산식은 변경하지 않았다.
- [x] 로컬 D1에서 3개월 경계 1ms 전·정확한 경계, 월말·윤년, 모든 상태, 멤버 동반 삭제, 최근 기록·다른 서버 최근 기록 보존, 대상 없음과 FK 오류 없음을 검증한다. 기본 내보내기의 scheduled에 설정 파일의 실제 cron을 전달하고 DB 오류가 밖으로 나가지 않는지와 로그를 검사한다.
- [x] 카드 번호·옵션 중복 제거·20개 제한·빈 목록, 재게시 권한·공개 응답·무알림, 다른 채널 완료 리액션, callback 실패 뒤 알림 복구와 DB 비교 fallback을 테스트한다.
- [x] 등록 모드 없음·오류·서버 ID 누락은 API 호출 없이 실패하고 전역/서버 경로·필드·토큰 비출력을 검사한다.
- 과거 0.3.0·0.4.0 로컬 회귀 검사와 비밀값 없는 Wrangler HTTP 스모크를 수행했다. 당시 테스트 수는 그 시점의 기록이며 현재 수와 다르다. 과거 Claude 계열 독립 리뷰 기록은 이번 변경의 독립 리뷰를 뜻하지 않는다.
- 이번 작업은 원격 D1·배포·명령 등록·Discord API 호출을 실행하지 않는다. 버전은 0.4.0으로 유지한다.

## 5. 유지하는 결정과 한계
- 내역은 현재 서버의 취소 건을 제외한 최근 10건이며 페이지 넘김은 없다. 취소 기록은 조회 제한을 차지하지 않고 생성 후 3개월 보관한다.
- 비율 저장은 모든 부모·멤버 UPDATE에서 서버·분배자·active·등록/구매자 없음 조건을 확인하고 하나의 batch로 처리한다. 0% 파티원은 제외하지만 다시 조정할 수 있다.
- 동시 클릭의 DB 상태는 조건부 UPDATE로 보존한다. 늦은 카드 응답은 화면을 오래된 상태로 만들 수 있으며 권한 있는 사람이 다시 누르면 최신 상태를 그린다. 자동 동기화는 없다.
- 등록·구매 callback/알림 실패에도 DB는 유지한다. 비율 알림 복구는 재제출 때만 동작하며 다른 카드들까지 자동으로 갱신하지 않는다. 토큰이 없으면 상태 응답만 하고 알림·리액션은 건너뛴다.
- Workers Logs는 켜져 있다. 장애 확인에는 `npx wrangler tail`이나 Workers Logs를 쓰고 불필요한 사용자 정보·SQL 바인딩·토큰을 남기지 않는다.
- [ ] 구매 완료 오클릭 되돌리기와 취소 확인 단계는 없다. 마지막 구매는 즉시 완료가 된다. 별도 기능이 필요한지는 추후 결정한다.
