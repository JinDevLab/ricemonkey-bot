## 2. 이번 구현
- [x] `/분배패널`과 같은 입력 창을 공유하는 비공개 시작 버튼을 구현했다. 일반 텍스트 채널·봇 권한·확인 가능한 파티원 채널 보기 권한을 검사하고, 본인 전용 지연 응답 뒤 비공개 스레드 생성·순차 초대·DB 저장·카드 게시를 한다. 실패 시 공개로 대체하지 않는다.
- [x] 0003 `private_thread` 마이그레이션과 카드 POST 4xx(429 포함) 시 원자적 멤버·분배 삭제, 정리 실패 시 `/미완료` 안내를 추가했다. 5xx·네트워크 오류는 행을 유지하고 스레드 확인 후 카드가 없으면 복구하도록 안내한다. 저장 예외도 삭제를 시도하며 삭제까지 실패하면 저장 결과 불명확과 `/미완료` 확인을 안내한다. 비공개 재게시는 원래 스레드에만 멘션 없이 게시한다. 공개 `/분배`, 계산식, 자동 삭제, 조회 목록 표시는 유지한다.
- 비공개 스레드 변경은 1.1.0으로 배포하고 원격 마이그레이션·전역 명령 등록을 완료했다. 등록 상태 조회는 실제 분배 동작 검증을 뜻하지 않으며, 아래 실환경 미확인 항목은 그대로 남아 있다.
- [x] 생성 후 달력 기준 3개월이 지난 모든 상태의 분배를 매일 KST 03:00에 삭제한다. UTC 월말을 보정하고 경계와 같은 기록은 남긴다. 하나의 D1 batch에서 멤버를 먼저 삭제한다. 성공 로그는 `retention purge` 라벨과 건수, 실패 로그는 `retention purge failed` 라벨과 마스킹한 오류 이름·메시지를 남기고 다시 throw하여 Cron 이벤트를 실패로 기록한다. DB 바인딩이 없어도 같은 경로로 실패한다.
- [x] `/미완료`는 올릴 건·구매할 건 각각 오래된 순 11행을 조회해 10행씩 보여 준다. 같은 분배에 같은 번호를 붙이고 최대 20개 고유 분배를 선택해 원래 채널에서만 공개 카드를 다시 올린다. 분배자·제외되지 않은 파티원만 허용하고 다른 채널·종료 건은 거절한다. 본인 목록에 없는 등록 완료 건은 분배자가 다시 올리며, 원래 채널이 삭제되면 재게시하지 못하고 생성 후 3개월 뒤 자동 삭제된다. 알림을 다시 울리지 않으며 옛 카드도 동작한다.
- [x] 완료 리액션은 생성 채널이 아니라 버튼을 누른 메시지의 채널에 보낸다.
- [x] 비율 변경 알림 대상은 DB 금액 변경자와 제출 카드가 새 금액과 다른 파티원의 합집합이다. callback 실패 뒤 같은 값으로 제출해도 알림을 복구한다. 본문을 읽지 못하면 DB 비교만 쓰며 자동 재시도는 없다.
- [x] 명령 등록은 `npm run register:global`과 `npm run register:guild`로 명시한다. 전역은 서버 ID를 무시하고 서버 등록은 ID가 필수다. 서버 지정 명령은 전역과 겹쳐 보일 수 있다.
- [x] MIT 라이선스, [개인정보 안내](privacy.md), 문의와 운영자 삭제 요청 절차를 추가했다. 완료·취소 기록도 생성 후 3개월 보관 뒤 자동 삭제한다.
- [x] Node 24에서 설치·타입 검사·테스트·배포 dry-run을 실행하는 비밀값 없는 CI를 추가했다. CD는 보류하고 수동 릴리스를 따른다. CI 필수화 ruleset은 아직 설정하지 않았다.

## 3. 로컬 검증과 제약
- [x] 독립 리뷰 지적을 반영한 비공개 분배 변경의 타입 검사·전체 테스트 314개·배포 dry-run을 통과했다. dry-run은 비밀값 없는 임시 환경 파일을 명시해 `.dev.vars`·`.env`를 읽지 않았다. 실제 Discord API는 호출하지 않았다.
- [x] 비공개 경로는 채널 종류·권한별 거절, 모달 재사용, 입력 오류·토큰 없음·파티원 채널 권한 거절, 스레드·초대·저장·게시·지연 응답 실패, 삭제 롤백과 정리 실패 복구 안내, 게시 순서·이름 제한·멘션·DB 플래그, 비공개 재게시와 스레드 상호작용을 fetch mock·로컬 D1로 검사했다. 이는 Discord의 실제 알림 위치나 보관 해제 확인은 아니다.
- [x] 테스트는 Wrangler `getPlatformProxy({ persist: false, envFiles: ['test/.no-secrets.env'] })`의 실제 로컬 D1과 마이그레이션을 쓴다. 환경 파일은 존재할 필요가 없다. `envFiles: []`는 `.dev.vars` 자동 로드를 막지 못하므로 쓰지 않는다.
- [x] Ed25519 키는 테스트마다 생성하고 Discord 요청은 가짜 토큰과 fetch mock으로만 검증한다. 등록 스크립트도 Node 자식 프로세스에서 fetch를 교체하므로 실제 API를 호출하지 않는다. 계산식은 변경하지 않았다.
- [x] 로컬 D1에서 3개월 경계 1ms 전·정확한 경계, 월말·윤년·연도 경계, 모든 상태, 멤버 동반 삭제, 최근 기록·다른 서버 최근 기록 보존, 대상 없음과 FK 오류 없음을 검증한다. 두 번째 DELETE가 실패하면 멤버 삭제도 롤백되는지 확인한다. 기본 내보내기의 scheduled에 실제 cron을 전달하고 직접 호출·executionCtx.waitUntil 경로의 성공·실패, DB 오류 전파와 마스킹한 로그를 검사한다.
- [x] 카드 번호·옵션 중복 제거·20개 제한·빈 목록, 재게시 권한·공개 응답·무알림, 다른 채널 완료 리액션, callback 실패 뒤 알림 복구와 DB 비교 fallback을 테스트한다.
- [x] 등록 모드 없음·오류·서버 ID 누락은 API 호출 없이 실패하고 전역/서버 경로·필드·토큰 비출력을 검사한다.
- 과거 0.3.0·0.4.0 로컬 회귀 검사와 비밀값 없는 Wrangler HTTP 스모크를 수행했다. 당시 테스트 수는 그 시점의 기록이며 현재 수와 다르다. 과거 Claude 계열 독립 리뷰 기록은 이번 변경의 독립 리뷰를 뜻하지 않는다.
- 자동 삭제·카드 재게시·알림 복구와 독립 리뷰 반영 작업에서는 원격 D1·실제 배포·명령 등록·Discord API 호출을 실행하지 않았고 버전도 올리지 않았다. 로컬 검증은 실환경 확인을 대신하지 않는다.

## 5. 유지하는 결정과 한계
- 파티원 추가가 `invitable: false` 때문에 막히면 소유자가 정한다. 권장은 `invitable: true`(파티원이 다른 사람을 초대 가능)이고 대안은 봇에 Manage Threads 부여(모든 비공개 스레드 열람 가능)다.
- 봇의 권한 부족 안내 문구(`src/index.ts`)는 `스레드에서 메시지 보내기`로 표시한다. 한글 화면 이름 `스레드와 포럼에서 메시지 보내기`와 다를 수 있어 다음 코드 릴리스 때 맞춘다.
- 긴 순차 REST 호출에 시간 제한이 없어 지연 시 응답이 멈추거나 카드 없는 기록이 남을 수 있다. 자동 재시도는 하지 않는다.
- 내역은 현재 서버의 취소 건을 제외한 최근 10건이며 페이지 넘김은 없다. 취소 기록은 조회 제한을 차지하지 않고 생성 후 3개월 보관한다.
- 비율 저장은 모든 부모·멤버 UPDATE에서 서버·분배자·active·등록/구매자 없음 조건을 확인하고 하나의 batch로 처리한다. 0% 파티원은 제외하지만 다시 조정할 수 있다.
- 동시 클릭의 DB 상태는 조건부 UPDATE로 보존한다. 늦은 카드 응답은 화면을 오래된 상태로 만들 수 있으며 권한 있는 사람이 다시 누르면 최신 상태를 그린다. 자동 동기화는 없다.
- 등록·구매 callback/알림 실패에도 DB는 유지한다. 비율 알림 복구는 재제출 때만 동작하며 다른 카드들까지 자동으로 갱신하지 않는다. 토큰이 없으면 상태 응답만 하고 알림·리액션은 건너뛴다.
- Workers Logs는 켜져 있다. 장애 확인에는 `npx wrangler tail`이나 Workers Logs를 쓰고 불필요한 사용자 정보·SQL 바인딩·토큰을 남기지 않는다.
- [ ] 구매 완료 오클릭 되돌리기와 취소 확인 단계는 없다. 마지막 구매는 즉시 완료가 된다. 별도 기능이 필요한지는 추후 결정한다.
